# Template render fallback, 2026-09-29

A saved template can pass validation and still throw during rendering. The item-level boundary previously showed only “This item could not be displayed,” hiding the saved title and body in the reader. Missing template definitions already select a built-in look; this change covers a render-time failure.

The full reader boundary now shows the saved title, subtitle, full body, fields, tags, and asset references without interpreting the broken template. Asset links use the existing safe-link check. A failed collection card shows its title without expanding a full document into the folder. Neighbouring items stay visible. The underlying document, template revision, save path, and edit controls are unchanged. The fallback is a plain-text recovery view, so Markdown source remains legible but is not formatted there.

Focused server-render tests forced a child renderer exception. They confirmed full-reader content remained present, the collection card stayed compact, a neighbouring item rendered, private exception text was absent, and an unsafe asset URL did not become a link. The existing malformed-template sync tests confirmed unreadable look data does not reject saved words. **46 tests passed** across the two focused files; TypeScript and touched-file ESLint passed. A headless browser check of the rendered fallback found legible content with light foreground/background `rgb(29,29,31)` / `rgb(255,255,255)` and dark `rgb(245,245,247)` / `rgb(29,29,31)`. This is source/test evidence, not a new installed-app or live malformed-template check.
