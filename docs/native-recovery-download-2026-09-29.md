# Native recovery download and stale outbox, 2026-09-29

The installed development-signed Store-shaped app was replaced locally with **0.202 (1113)**, still pointed at `http://localhost:3000`. The installer verified its signature, Apple silicon executable, three extensions, and one canonical running app. The sandbox-private runtime health report could not be read by the installer, so runtime health remains unverified. No public build or website changed.

On the local scratch note `Typing benchmark 7d924acf`, the recovery screen had previously enabled **Open current version** after a WebKit blob link click without evidence that a file was saved. Build 1113 routes WebKit downloads through a Mac save panel and reports completion to the editor. The editor now waits for that completion. The native save panel appeared, the control stayed disabled until saving finished, and a 3,783-byte JSON recovery copy existed in Documents. Cancellation and timeout keep it disabled in focused tests. Browser downloads retain the existing click path.

The note then exposed a second defect: acknowledgment removed a quarantined copy, but a stored outbox with unknown epoch `0`, one update, and an exact baseline was repeatedly retired after the in-memory writer learned epoch `1`. The old equality check treated those as different generations despite the saved copy covering the stored baseline and update. A separate local recovery copy could appear before the retired record finished writing. The code now retires an unknown-epoch row only when its baseline matches exactly and every stored update is in the exported copy; newer or unmatched work stays in the outbox. Before reopening, the editor checks for newly arrived recovery copies and requires each to be saved.

Live verification saved the remaining copies through the native panel, including a retired copy whose baseline and update exactly matched the stored row. After acknowledgment, the installed app reopened the note with its text intact and **Saved** visible. The temporary diagnostic control used to inspect epoch and coverage was removed. The saved JSON files remain in `~/Documents` as recovery evidence; none were deleted. This validates the observed case, not all corrupt or concurrent outbox states.
