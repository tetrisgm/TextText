After a production build ran against the same `.next` directory as the long-running development server, that server began rejecting the saved look's `showCaptions` property and returned 500 for the whole workspace pool. The current source accepts that property, and a fresh process validated the stored definition. A stale development module is the likely cause, but it has not been confirmed by restarting the server.

In the isolated `Folder view proof 2026-09-28` fixture, a note appeared under **Unsaved items** with a retry action. A direct read from local Postgres confirmed the exact note title and body were already saved once. The UI still could not clear its stale recovery card while workspace refresh returned 500. The same retry key is reused, so the pending UI retry is designed to reconcile with that saved item rather than create another one. Do not discard the card until a successful receipt is shown.

The document content and exact pinned reference are not rewritten. A bounded warning names the look version without logging its definition or private content. Local database tests covered an invalid latest version, valid predecessor, exact and pinned lookup, and library history; a pool test covered fallback rendering. Eight focused tests, TypeScript, and touched ESLint passed (two existing store warnings).
