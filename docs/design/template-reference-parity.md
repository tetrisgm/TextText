# Template reference parity audit

Checked October 2, 2026 against the current source, the local browser fixture, and the public reference pages. A passing fixture proves the named TextText behavior, not a visual or interaction match to another product. The owner asked for creation, editing, and reading fidelity in every surface, using TextPack files underneath. None of the six surfaces is proven complete.

| Surface | Current evidence | Remaining product gap / proof needed |
|---|---|---|
| Bookmarks, [Shiori](https://www.shiori.sh/) | `VaultBookmarkLibrary.tsx` has URL capture, direct URL paste on the inbox, an on-demand Add link form, filters, reader/original switch, contextual details, and an editable Summary stored in the Bookmark TextPack subtitle. The reader presents that Summary as a full-width card beneath the source; it expands and collapses without changing the saved subtitle. A failed capture keeps the link and offers Retry capture in the reader; the fixture checks that retry preserves authored body text. `verify-browser.mjs` covers capture, navigation, search, summary persistence, pointer and keyboard toggling, card layout in both themes, and TextPack writes. | Compare real image, article, video, and failed-extraction cases with Shiori's list and reader. TextText does not automatically generate a per-link summary or capture transcripts/PDF content as Shiori does. Verify capture and edit on Mac and web with real content, not only fixture text. |

## Next implementation sequence

1. Recover or replace the missing Artifact originals before making more claims of visual match, then implement automatic reading progress and profile using actual reader activity. Do not invent history from feed items merely loaded into memory.
2. Build realistic, reusable reference fixtures for each content type: a long article with images, mixed bookmarks, a photographic Gallery, and rich notecards. Capture both themes and narrow/desktop widths.
3. Compare each creation, edit, and read path side by side against the reference, record specific mismatches, and fix them in priority order. Keep the same TextPack primitives and conflict behavior underneath.

The existing `docs/HANDOFF.md` remains the current-work ledger; this audit is the requirement map. No release is implied by source checks or a push.
