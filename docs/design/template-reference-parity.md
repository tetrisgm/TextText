# Template reference parity audit

Checked October 2, 2026 against the current source, the local browser fixture, and the public reference pages. A passing fixture proves the named TextText behavior, not a visual or interaction match to another product. The owner asked for creation, editing, and reading fidelity in every surface, using TextPack files underneath. None of the six surfaces is proven complete.

| Surface | Current evidence | Remaining product gap / proof needed |
|---|---|---|
| Bookmarks, [Shiori](https://www.shiori.sh/) | `VaultBookmarkLibrary.tsx` has URL capture, an inbox list, filters, reader/original switch, and contextual details. `verify-browser.mjs` covers capture, navigation, search, and TextPack persistence. | Compare real image, article, video, and failed-extraction cases with Shiori's list and reader. The public preview includes summaries and feeds; TextText has no equivalent per-link summary experience in this reader. Verify capture and edit on Mac and web with real content, not only fixture text. |

Import, paste, drop, and detail edits have browser checks. | Compare a real photographic library and image detail against Resurf's justified grid and inspector. The fixture's flat color blocks cannot prove spacing, image handling, or visual hierarchy. Check multi-image TextPacks, GIFs, and narrow windows on Mac and web. |
| Feeds, Artifact News | `VaultFeedHeadlines.tsx` has interests, For You, topic tabs, Headlines, Latest, Read Later, source management, and an article reader. `docs/plans/artifact-home-replication.md` describes the fuller target. | Reading History and profile/stats are absent from the local Feeds UI; read state currently centers on kept stories. TextText's browser fixture proves its own interaction contract, not exact command parity. |

## Next implementation sequence

1. Recover or replace the missing Artifact originals before making more claims of visual match, then implement the local Feeds History/profile and reader gaps using real read state. Do not invent history from unsaved feed items.
2. Build realistic, reusable reference fixtures for each content type: a long article with images, mixed bookmarks, a photographic Gallery, and rich notecards. Capture both themes and narrow/desktop widths.
3. Compare each creation, edit, and read path side by side against the reference, record specific mismatches, and fix them in priority order. Keep the same TextPack primitives and conflict behavior underneath.

The existing `docs/HANDOFF.md` remains the current-work ledger; this audit is the requirement map. No release is implied by source checks or a push.
