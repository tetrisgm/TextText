## Architecture findings

- The same workspace UI and validated document model are used across the three surfaces. `document-session.ts` now owns client/checkpoint/presence lifetime outside React; [T08 source and host checks pass](2026-10-17-shared-session-ownership.md).
- Browser, Mac and Windows durability adapters differ by design. Browser persistence, native checkpoints and file materialization need one typed contract, while retaining platform-specific filesystem primitives.
- Mac `LocalVaultSync.swift` and Windows `TextText.Core/SyncEngine.cs` both implement background file synchronization policy. The shared Yjs client does not replace those engines; the runtime choice and no-editor behavior are recorded in the [shared runtime decision](shared-runtime-decision.md), while policy migration still needs adapter conformance evidence.
- The public workspace pages and the authenticated `/vault/[workspaceId]` application are distinct routes. Do not treat public reading as the native app home route. Audit the owner’s older home-route expectation against the current installed behavior before removing either path.
- No parity row is accepted from code presence alone. Installed light/dark behavior, editing, search invalidation, comments, sharing, templates, agents, recovery, account changes and platform input conventions still require receipts.

## Portable policy host plan (T10 → T11)

Use the existing packaged page runtime for shared TypeScript policy; do not add JavaScriptCore hosting, Node, a daemon, or copied Swift/C# algorithms. Native adapters continue to own filesystem CAS, locks, credentials, durable write primitives and process lifecycle.

Host feasibility is visible in current code: Mac `AppDelegate.applicationShouldTerminateAfterLastWindowClosed` returns false and retains `localVaultWindow`; `LocalVaultWindowController.windowWillClose` stops its agent but keeps the controller, WebView and connection. On Windows, `App.Main` runs the main window and `MainWindow.Closed` disposes the bridge and WebView together. There is no independent Windows mirror process to host policy after exit. A home page or closed Mac window can therefore retain the existing policy module without retaining an editor or introducing another runtime. Web has no filesystem mirror.

Implement the migration in this order:

1. Export a versioned, pure policy request/reply function from the packaged shared bundle. Inputs are validated snapshots, file/baseline fingerprints, pending intent metadata and capabilities; credentials and native paths remain native. Begin with reconciliation disposition. Native core receives an async policy interface; app adapters call the existing WKWebView/WebView2. Both use the same bundled implementation and fixture vectors.
2. Gate mirror startup on a version/digest readiness handshake. Requests carry workspace/account/lifecycle/request identity; callbacks from a replaced page or account are rejected. If the page is absent, restarting or crashed, pause mutation and retain queues. Do not silently fall back to the old algorithm after a new policy lease has started.
3. Keep a single native workspace writer lease throughout policy evaluation and file CAS. Editor and mirror requests reuse their own actor's lease; foreign actors remain excluded. A reply is a proposed action against captured fingerprints, never permission to overwrite changed bytes.
4. Prove actual WKWebView/WebView2 evaluation on home, after editor close, while the Mac window is closed, on process reload, and offline. Existing native transport failures, cold-start/idle memory and scheduling bounds remain acceptance gates. A hidden page's background scheduling is a measurable constraint, not assumed equivalent to a foreground page.
5. Switch one disposition branch in both adapters only after identical production-host fixtures pass. Remove its old native decision branch only then. Repeat for retry/outbox decisions, followed by lifecycle policy. Keep durable IDs, native atomic writes and backward-compatible queues throughout.

This is an implementable host plan, not completed consolidation. Existing native background algorithms remain the authoritative production path until each replacement slice passes. Shared active-document ownership and OS exclusion are already implemented; portable mirror policy is still T11 work.
