# Portable server creation destinations

The actual server folder-view GET bug produced three trailing-space names that native clients reject globally. New file-backed `create_item` destinations, including a folder chosen after template resolution, had a second path to the same class of invalid names. The create path now rejects nonportable parent components before any destination directory is made. This is creation-only: existing reads, updates, receipt replay, alias checks, and native catalog guards remain unchanged. The subsequent feed adapter will use the same validation before any publisher fetch.

Mac production-store baseline failed six invalid-destination controls; the corrected store passed 12 focused cases, including suffix-space/dot, reserved and nested names, full tree-byte equality, zero audit receipts, and template-selected paths. The adapter baseline failed eight controls; corrected adapter passed 17, including no fetch/write/audit on refusal and valid Unicode/root paths. TypeScript passed on the PC. Evidence: Mac `/private/tmp/texttext-feed-command.Drsrma/` and PC `%TEMP%/texttext-feed-command-9f54c838667f4b08bb576d4f0bc382a4/portable-receipt-draft.md`. Live acceptance awaits the next release; the three retained empty folders were not changed.
