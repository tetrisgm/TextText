# Retained replacement recovery UI

Source verification on October 18, 2026. This receipt does not claim an installed or deployed build.

The shared recovery dialog shows interrupted saves supplied by a capable native bridge. It reads the visible file, retained save attempt, and displaced version before enabling **Keep current file**. Each response must match the captured path and content hash and include complete bytes. Current and prepared versions require the captured stable item identity. A displaced version may belong to another document; the UI identifies that case. Displaced bytes that cannot be parsed remain downloadable as a binary file with their exact hash and do not receive fabricated document content. Users can inspect each text preview, complete pack hash, and attachment filename/type/byte count/SHA-256. Each verified version can be downloaded as a complete TextPack using a fixed safe filename. Restore as a new file uses the existing save barrier; a blocked restore leaves downloads available without requiring a successful editor save. Explicitly resolved records remain inspectable and downloadable on reopen, including opaque bytes, with the Keep action hidden. If a retained descriptor changes its bytes, the record becomes unresolved again and requires fresh inspection. The explicit action acknowledges the observed three versions; the native registry must export both retained snapshots before acknowledging them and must never replace the visible file as part of this action.

Opening recovery now leaves the editor draft mounted and does not require a successful save. Existing restore-as-copy and Trash restore still require their own save barrier. Keeping the visible file does not reload, discard, or claim to save the editor draft. A changed file or failed resolution clears the inspection and requires a fresh inspection before another attempt.

The dialog captures its transport and aborts or ignores replies after unmount. Workspace and account identity changes hide the original dialog. Native replacement list/read/resolve calls check the captured root, connection and account before work and before replying. Unsupported bridges omit the optional replacement list; registry errors remain visible errors.
