# Mac local install (October 12)

The local Store-shaped Mac app was built from a pristine archive of commit `7ba3400e`; the source fingerprint is `cedbc88fd61d51c7366bdc42346c7af7b94d96024d7a2a563ba28de553b4f680`, matching the Windows candidate's source. Existing local provisioning profiles and the signed Codex helper were linked into the isolated build directory. The build used local PostgreSQL, passed 918 UI tests and the native checks, and signed all three extensions. The installed bundle is `/Applications/TextText.app`, version 0.204 build 1260, signed with Apple Development and preserving the native Apple sign-in shape. Installation used the recoverable swap in `mac/scripts/install-local.sh`; the prior bundle's Trash destination was not independently inspected because shell access to Trash was denied.

The install script verified the signature and Apple silicon bundle and launched one canonical copy. Through the installed UI, the existing `Six-client acceptance close diagnostic 176` note opened with its expected body; the app quit normally and reopened to the same note with the account signed in. No recovery notice appeared in the observed UI.

The local Store build has no release-gate or workflow attestation. Its `TEXTTEXT_HEALTH_CHECK=1` report consequently returns `fail` for attestation and workflow receipts, even though its bundle checks and runtime self-tests pass. The install used the documented local-development `TEXTTEXT_REQUIRE_RUNTIME_HEALTH=0` path. This is a local install, not a public Mac release. A full attested delivery and broader physical acceptance remain open.
