# Windows folder spelling and metadata recovery

## Scope

Same-parent directory spelling changes use the existing folder catalog, not a new folder-ID or move RPC. The complete catalog is validated before managed-folder state/materialization; contradictory spellings of one directory refuse. Distinct directories in a case-sensitive parent remain separate. Exact spelling is checked across every relative path component, so retirement of `Notes` cannot delete the authoritative `notes` alias. Sync rescans after materialization. Existing shared move intents adopt an already physically changed parent path without renaming each child or changing pending batch bytes, identity, epoch, sequence or generation. A file command cannot implicitly rename an unchanged parent.

The native operation opens the source directory with DELETE access without FILE_SHARE_DELETE and pins its parent chain. A durable device-private intent binds the initial source and parent volume/file IDs before source-pin observation. The source handle must attest those initial identities. `SetFileInformationByHandle(FileRenameInfo)` performs one direct rename with replacement disabled; exact destination spelling and identity verify before completion. A pre-pin source replacement persists conflict and leaves the foreign directory unrenamed. No intermediate directory, overwrite, rollback or directory-content backup is used.

Pending restart classifies only exact unchanged original/absent destination as cancelled, or absent original/exact expected destination as completed. Other observed states fence ordinary workspace reads, writes and ACKs. This first implementation uses a conservative global fence. Device-private operation records stream without a lifetime count cap or automatic deletion; normal validation remains proportional to folder-operation history.

## Ownership and recovery

Owned mutations first publish replacement profile version two, preserving exact `profile-v1.json` and the actual displaced `profile-v1-displaced.json`. Owner version two and the semantic principal remain unchanged. Interrupted publication resumes only with exact proof; changed displaced profile bytes refuse even in an already-open empty workspace. Unowned local roots retain ordinary exact creation/read, but case mutation requests existing-account review before any folder intent or native mutation. The floor applies to account factories that check this profile; it cannot make arbitrary historical binaries or raw filesystem writers honor a marker they never read. Historical installed-reader acceptance is separate.

Recovery list/read bypass the normal content fence while independently checking owner, root and profile. They report exact endpoint presence and file identities, plus a digest of bounded metadata inspection. Inspection permits at most 10,000 entries and 4 MiB of metadata; unsafe, unreadable or incomplete inspection blocks consent. An uninspectable endpoint is not claimed absent. This is metadata inspection, not a copy or content-hash guarantee for directory trees.

Explicit consent rechecks the inspection and captured scope, retains an immutable receipt and changes neither directory nor its contents. Cancellation leaves the intent unresolved. Resolved records remain inspectable and permit later legitimate directory renames and descendant edits. Unknown journal/consent fields, changed ownership and copied-root records refuse. The Windows bridge verifies captured root/workspace/account before/after access and immediately before durable acknowledgement; metadata access remains available with ordinary requests or network work stalled.
