## Mechanism and limits

The [driver contract](../../sync/stress/README.md#one-browser-response-lost-after-commit) adds one isolated real `lostAck` round, targeted at mac-web or pc-web. All six roles and complete binary asset pins remain mandatory. The fault creates no content write: normal keyboard input produces the original authenticated collaboration POST. A response-stage CDP interception binds the actual main frame, item and route. It verifies the existing account-scoped durable batch, actual successful HTTP200 result and fresh authenticated full-pack marker/path/identity/assets proof before failing original response delivery once.

Partial typing batches continue unchanged until the selected complete marker is committed exactly once. The production client must then retry the exact operation ID/raw payload SHA. The original successful replay response is continued unchanged. Three fresh all-six snapshot/assets/editor-session observations follow delivery. The response fault is accounted separately from six semantic edits; independent zero-round reopen binds the prior completed fault receipt, same scenario, final body/document/assets and artifact/account pins. No native response-loss, binary recovery, deletion, general lifecycle, mixed schedule or full-matrix completion is claimed.

No `route.fetch`, replacement HTTP writer, fabricated ACK, new account/token/profile, product endpoint, native actor change or installed-app action was used. Journal observation opens only an existing IndexedDB database in readonly mode. Unknown schema/owner/frame, missing evidence, non200 response, overlapping responses or changed immutable replay refuse acceptance. Active callback accounting prevents disabling Fetch while another response body/proof callback is outstanding; a shared fatal error is rechecked after awaits before continuing or losing a response.
