# Mac assistant feed proposal adapter

The built-in native assistant previously offered only local file tools, so the reviewed `add_feed` command committed in `20baf011` was not reachable from a folder task. The adapter advertises `propose_feed` only for a connected, non-root folder task. It captures the selected folder, verified account and workspace binding, and sends only `proposal:add_feed` through the existing authenticated command API. It checks authority again after the reply, suppresses canceled or stale task results, and requires an approval receipt with a proposal ID and credential-free HTTPS review link. Fetching and creation remain server-side after owner review.

Mac `swift test` focused on `LocalVaultAgentControllerTests` and `LocalVaultFeedProposalTests` passed, including captured destination, cancellation, account change, and malformed-receipt cases. The broader connection/lifecycle group passed 24 tests (3 intentionally skipped) with the release Node runtime on `PATH`. An initial invocation without Node on `PATH` failed to start mirror-policy helper work; it was not counted as a product pass. Independent source review found no authority or cancellation blocker. Installed assistant acceptance and the next unified release remain pending.
