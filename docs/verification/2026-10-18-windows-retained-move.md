The deterministic final-boundary fixture replaces the source with a different valid document immediately before native rename. The previous store returned success and moved those foreign bytes; `/private/tmp/texttext-t13-move-red-mac.log` preserves the failure. The new helper durably registers a versioned two-path move intent and immutable expected baseline before mutation, holds a device-private operation lease, pins Windows parent directory chains, requires the same volume, and verifies actual destination bytes before reporting success. A mismatch retains actual bytes at their destination without rollback and fences the expected identity plus both original paths, including Windows case aliases. Its observed destination snapshot is an immutable copy, not a claim to a hidden retained inode.

Recovery lists and reads expose source/destination presence and exact hashes, the expected baseline and an optional observed snapshot. Foreign parsed files retain their actual identity; absent versions return explicit absence. Exact uncaptured unchanged intents cancel on restart; a completed native rename interrupted before snapshot publication reconstructs only after exact verification. A private operation lease prevents another store from cancelling an active capture. Automatic completed moves permit later visible edits; changed retained snapshots reopen a visible recovery row.

Explicit Keep current files verifies both paths and all available versions, exports complete immutable copies, rechecks before and after the captured scope callback, and writes durable consent without changing either path. Cancellation after exports leaves the operation unresolved and alternatives retained. A relocated or duplicate expected identity blocks consent while baseline/downloads remain available. Unrelated items and paths continue operating.

## Same-parent case-only filenames

A focused red reproduced the baseline rejection of an existing destination alias (`/private/tmp/texttext-t13-case-only-red-mac.log`). The bounded extension supports leaf spelling changes within exactly the same parent. It qualifies an alias only when the directory contains the exact source leaf but no exact destination leaf, and Windows confirms identical volume/file identity. The private manifest and registry bind `CaseOnly:true`; recovery probes exact directory-entry spelling instead of treating both case aliases as present. The bridge wire is unchanged.

The existing no-overwrite native move changes the leaf directly, with no intermediary filename or rollback. Exact new spelling and actual bytes must verify before success. Restart fixtures cover interruption before capture, after native rename, and after observed snapshot creation. A final raced foreign source remains at its actual new spelling; old spelling is reported honestly absent and explicit consent changes neither bytes nor spelling. An isolated actual-PC per-directory case-sensitive fixture successfully created two distinct case-fold-equivalent files and proved both remain unchanged when rename is refused. Only that newly created scratch directory's case-sensitive flag was enabled; no hostwide setting changed.
