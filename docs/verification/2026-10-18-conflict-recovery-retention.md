# Conflict recovery byte retention

Bounded T14 source slice. Installed and complete conflict acceptance remain open.

## Invariant

An operation cannot be retired on the strength of a remote-only recovery copy. Mac upload/rename conflicts now require coherent staged bytes matching the original hash. Legacy deletion history remains optional, but present bytes must validate. Recovery files are created without overwrite, existing copies are verified, and required copies are flushed before retirement. A failed journal write restores the operation's affected in-memory fields without replacing other documents' newer state.

Windows binary conflict recovery now preserves the exact originally submitted asset separately from the current local pack and remote winner. The staged payload is revalidated after network awaits. Existing recovery files are verified rather than trusted by their filenames; corrupt copies remain untouched. Legitimate asset deletion remains distinct from a missing required payload. Legacy embedded asset bytes and staged file reads are bounded.
